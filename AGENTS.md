# AGENTS.md — Business Context: Expense Tracking App

Domain document. Describes **what** the app does and **why**. Contains no code style rules (see `CLAUDE.md`) and no execution steps (see `plan.md`).

---

## 1. Purpose

Personal mobile app (single-user, offline-first) to record expenses, know how much money is left in each payment method, and get reminders for recurring bills.

Principles:
- **Offline-first**: no backend. Everything lives on the device (MMKV).
- **Single user**: no login, no accounts, no sync.
- **Record an expense in under 10 seconds**: the "new expense" flow is the most important screen in the app.
- **Single currency**: the app stores plain numbers and formats them with one configurable currency code. No conversion between currencies.

## 3. Data Model

Key-value persistence in MMKV. No SQL. Each collection is a serialized array under a Zustand store key.

### 3.1 `Category`

```ts
type Category = {
  id: string;
  name: string;
  icon: string;         // icon name (lucide / ionicons)
  color: string;        // hex, used for chips and charts
  isDefault: boolean;   // true = preloaded, not deletable
  merchants: string[];  // user-defined autocomplete suggestions, empty on seed
};
```

### 3.2 `Wallet` (payment method)

```ts
type WalletType = 'cash' | 'debit' | 'credit' | 'prepaid';

type Wallet = {
  id: string;
  name: string;
  type: WalletType;
  color: string;
  balance: number;         // current balance
  initialBalance: number;  // balance the wallet was created with
  isDefault: boolean;
  archived: boolean;       // hidden from pickers, history preserved
};
```

### 3.3 `Expense`

```ts
type Expense = {
  id: string;
  amount: number;          // positive, 2 decimals
  categoryId: string;      // FK -> Category.id
  walletId: string;        // FK -> Wallet.id
  merchant: string | null; // free text entered by the user
  note: string | null;
  date: string;            // ISO 8601
  createdAt: string;       // ISO 8601
  recurringId: string | null; // FK -> RecurringPayment.id if generated by one
};
```

### 3.4 `Income`

```ts
type Income = {
  id: string;
  amount: number;
  walletId: string;
  source: string | null;
  date: string;
  createdAt: string;
};
```

### 3.5 `RecurringPayment`

A bill that repeats every month and triggers a local notification.

```ts
type RecurringPayment = {
  id: string;
  name: string;             // free text entered by the user
  amount: number;           // estimated amount
  categoryId: string;
  walletId: string;
  dayStart: number;         // 1-31, start of the payment window
  dayEnd: number;           // 1-31, end of the payment window
  notificationHour: number; // 0-23, local hour of the reminder
  active: boolean;
  lastPaidPeriod: string | null; // "YYYY-MM" of the last period marked as paid
};
```

### 3.6 `Budget` (optional, late phase)

```ts
type Budget = {
  id: string;
  categoryId: string | null; // null = global budget for the month
  amount: number;
  period: string;            // "YYYY-MM"
};
```

### 3.7 `Settings`

```ts
type Settings = {
  theme: 'system' | 'light' | 'dark';
  currency: string;      // ISO 4217 code, user-configurable
  monthStartDay: number; // 1-28, first day of the accounting month
  onboardingDone: boolean;
};
```

## 4. Preloaded Data (seed)

The seed runs **once**, on first launch, when `tracker.schemaVersion` does not exist. It never overwrites user data.

The seed contains generic defaults only. It must never ship brand names, merchant names, institutions, or any personal data. The user adds those at runtime.

### 4.1 Categories

| Category | Type |
|---|---|
| Housing | `isDefault: true` |
| Utilities | `isDefault: true` |
| Food & Groceries | `isDefault: true` |
| Transportation | `isDefault: true` |
| Entertainment | `isDefault: true` |
| Health & Fitness | `isDefault: true` |
| General Shopping | `isDefault: true` |

All seed categories start with `merchants: []`. Merchant suggestions are built up by the user: saving an expense with a new merchant name adds it to that category's list.

Default categories can be edited and archived, but not deleted.

### 4.2 Wallets

| Wallet | Type |
|---|---|
| Cash | `cash` |
| Credit Card | `credit` |
| Debit Card | `debit` |

`Cash` is the default wallet (`isDefault: true`). All start with `balance: 0`; the user sets the initial balance during onboarding or from the wallets screen.

### 4.3 Recurring Payments

The seed ships **no** recurring payments. The recurring payments screen starts empty, with an empty state prompting the user to add their first monthly bill (rent, utilities, subscriptions) with their own name, amount, day window and reminder hour.

## 5. Business Rules

### 5.1 Balances
- Recording an expense **subtracts** `amount` from `wallet.balance`.
- Recording an income **adds** `amount` to `wallet.balance`.
- Editing an expense reverts the previous movement and applies the new one (even if the wallet changed).
- Deleting an expense reverts the movement.
- A balance **may go negative**. Recording is never blocked: this is a tracker, not a bank.

### 5.2 Validation
- `amount` must be `> 0`. Zero and negative values are rejected.
- `categoryId` and `walletId` must exist. An expense is never orphaned.
- `date` cannot be in the future for an already-made expense.
- `dayStart` and `dayEnd` must be within 1-31 and `dayStart <= dayEnd`.
- Archiving a wallet or category keeps historical expenses intact and still visible.

### 5.3 Period
- The accounting month starts on day 1 by default. Configurable in settings (`monthStartDay`).
- The dashboard always shows the current period unless the user navigates to another one.

### 5.4 Local Notifications

The app reminds the user of monthly bills (rent, utilities, subscriptions) on a user-defined day window. Every name, amount and date comes from the user; nothing is hardcoded.

Rules:
- Every active `RecurringPayment` schedules **monthly repeating** notifications.
- Two reminders are scheduled per window: one on `dayStart` and one on `dayEnd`, at `notificationHour`.
- The `dayStart` reminder announces the payment window is open; the `dayEnd` reminder announces it is the last day. Both use the payment's own `name` in the message.
- If the user already recorded an expense linked to that `recurringId` in the current period (`lastPaidPeriod === current "YYYY-MM"`), the `dayEnd` notification is skipped when it fires.
- Notifications are rescheduled when: a recurring payment is created, edited, activated or deactivated, and on app launch.
- Deactivating or deleting a recurring payment cancels its pending notifications.
- Permissions are requested during onboarding. If denied, the app works the same and shows a notice on the recurring payments screen.
- Without notification permissions, the app **never** blocks functionality.

### 5.5 Dashboard
Shows, for the current period:
- Total spent and total earned.
- Consolidated balance (sum of non-archived wallet balances).
- Breakdown by category (amount and percentage).
- List of recent expenses.
- Recurring payments due in the next 7 days.

## 6. Out of Scope (v1)

Do not implement without an explicit request: multi-user, backend/sync, multi-currency conversion, spreadsheet export, receipt OCR, shared expenses, image attachments, native widgets.
